# Project Rules

1. Писать понятный Python-код с type hints и docstring для основных функций.
2. Сохранять модульную архитектуру: API, CLI, Streamlit и core-логика не должны смешиваться.
3. Не использовать платные API и внешние облачные сервисы.
4. Не добавлять тяжелые зависимости без необходимости.
5. Новую логику покрывать pytest-тестами.
6. При изменении запуска или интерфейсов обновлять README.md.
7. Все ошибки обрабатывать аккуратно и возвращать понятные предупреждения.
8. Не ломать существующий pipeline обработки PDF.
